# Pinly

**Визуальная лента идей: веб-аналог Pinterest, который работает в России без VPN,
без ключей и без третьих сторон.**

Картинки и видео приходят из открытых источников и из собственных загрузок,
аккаунты и доски лежат в вашем же Python-бэкенде на SQLite, оптимизацией
изображений занимается свой прокси. Один `docker run` — и сайт целиком ваш,
вместе с данными и файлами пользователей.

> ⚡ **TL;DR — три команды и адрес**
>
> ```bash
> npm ci && pip install -r backend/requirements.txt
> python -m uvicorn backend.app:app --port 8000   # аккаунты, доски, события
> npm run dev                                     # http://localhost:3000
> ```
>
> Без бэкенда сайт тоже открывается и работает — анонимно, с досками в
> `localStorage`. Это не урезанный режим, а обычный сценарий для демо на
> статик-хостинге.

**Нужно:** Node 22 и Python 3.13 (на них проект проверяется в CI), `ffmpeg` —
если собираетесь загружать видео. Без `ffmpeg` сайт работает: пин приезжает
без постера, а карточка держит первый кадр сама.

## 🚀 Чем отличается

- **Никаких третьих сторон в цепочке.** Ни S3, ни Cloudinary, ни OAuth-провайдер:
  файлы на своём диске, сессия на своём JWT, картинки через свой прокси.
- **Открытые источники контента.** Openverse, собрания Метрополитен и Кливленда,
  Wikimedia Commons, TheMealDB — всё без ключей и доступно из РФ.
- **Данные остаются у вас.** Один том с базой и загрузками; удаление аккаунта
  стирает всё без мягких копий.
- **IP и e-mail не пишутся в базу событий.** Посетитель — суточная HMAC-метка,
  из реферера остаётся только хост ([подробно →](docs/privacy.md)).

## 🎬 Видео и слайды

В пине до восьми носителей. Листают их свайпом, точками, стрелками и с
клавиатуры — всё одним механизмом нативного scroll-snap, без JS-анимаций.

- **Видео играет в ленте** тихо и по кругу; пауза — отдельной кнопкой, чтобы не
  спорить с кликом по карточке. На странице пина появляются перемотка и звук.
- **Обложкой всегда остаётся картинка.** Длительность и размеры снимает
  `ffprobe`, постер кадрирует `ffmpeg`, поэтому `og:image`, превью доски и сетка
  про видео ничего не знают и не ломаются.
- **Тип файла определяется по байтам**, а не по расширению: `mp4` с содержимым
  HTML не пройдёт.
- **Раздача умеет `Range`** — иначе Safari не играет ролик вовсе, а Chrome
  перекачивает его целиком на каждый шаг ползунка.
- **Грузится только активный слайд:** замер показал 2 МБ за 220 мс на играющем
  ролике и 0 байт на двух соседних карточках с видео.

Потолки: 10 МБ на картинку, 60 МБ на видео, 8 носителей на пин — одинаковые на
фронте и в бэкенде. Модель хранения — в [архитектуре](docs/architecture.md).

## 🛠 Быстрый старт

```bash
git clone https://github.com/Artemik0922/pinly-web && cd pinly-web

# 1. зависимости
npm ci
pip install -r backend/requirements.txt

# 2. бэкенд (аккаунты, доски, пины, события)
python -m uvicorn backend.app:app --port 8000

# 3. сайт
npm run dev            # http://localhost:3000
```

Работает и без шага 2: лента из открытых источников, доски и лайки в
`localStorage`. Так удобно смотреть репозиторий, но аккаунтов и чужих досок в
этом режиме нет.

Что почитать после запуска: [архитектура](docs/architecture.md) — как два
процесса живут на одном origin; [проверки](docs/testing.md) — четыре ловушки, на
которых тесты врут.

## 🌍 Откуда контент

| Источник | Что даёт | Категории |
| --- | --- | --- |
| [Openverse](https://api.openverse.org/v1/) | основной поток картинок (flickr, wikimedia и др.) | все |
| [Метрополитен-музей](https://metmuseum.github.io/), [Кливленд](https://openaccess.clevelandart.org/) | собрания общественного достояния | Искусство, Архитектура, Мода |
| Wikimedia Commons напрямую | общий фид и поиск | Природа, Путешествия и остальные |
| [TheMealDB](https://www.themealdb.com/api.php) | блюда с фотографиями | Рецепты |

Запросы кэшируются на диск (`.cache/`), а картинки отдаются через собственный
прокси `/api/img`. Один и тот же запрос уходит в API раз в сутки, поэтому
лимиты Openverse (анонимно 20 в минуту и 200 в день) перестают быть лимитами
сайта. Если источник недоступен, включается экспоненциальная пауза, его вклад
пустеет, а лента падает на локальные моки — пустых экранов не бывает. Автора
картинки и лицензию видно прямо на странице пина.

`npm run warm` прогревает кэш заранее. Без него первый посетитель платит
задержкой внешнего API, а не сайта.

## 🧠 Умная лента и поиск по фото

Оба включаются ключом `EMBED_API_KEY` и индексом `npm run index`; без них лента
остаётся обычной, и деградация прозрачна для пользователя.

- **Лента** для вошедших подбирает первые ~80% страницы по вектору вкуса
  (лайк = вес 1, сохранение = вес 2), остальные ~20% — обычная ротация
  категорий.
- **Поиск по фото** гоняет картинку через `voyage-multimodal-3.5` и ищет
  ближайшие векторы: модель мультимодальная, поэтому запрос-фото находит и пины,
  проиндексированные по тексту.

Честные состояния вместо пустой сетки: без ключа или индекса — 503 с
объяснением, что запустить; мусор вместо картинки — 400; больше 5 МБ — 413;
провайдер молчит — 502 и кнопка «Попробовать ещё». Порядок включения, лимит
частоты и почему формат запроса к роутеру пришлось подбирать перебором —
в [docs/embeddings.md](docs/embeddings.md).

## ✅ Проверки

```bash
npm run typecheck   # next typegen + tsc --noEmit
npm run lint        # eslint
npm run test:api    # pytest: валидация, права, каскады, кэш, носители — без сети
npm run test:e2e    # Playwright: лента, регистрация, комментарий, поиск, доска, видео
npm run ui:audit    # дизайн-система по вычисленным стилям (нужен сервер)
npm run build       # продакшн-сборка
```

Текущий прогон: **97 pytest**, **23 Playwright**, аудит **34 проверки** чисто.
CI ([`.github/workflows/ci.yml`](.github/workflows/ci.yml)) гоняет это тремя
работами: `frontend`, `backend` и `e2e`, которая стартует только после двух
зелёных.

Два предупреждения, которые экономят полдня: адрес прогона обязан быть
`http://localhost:3000` (не `127.0.0.1`), а бэкенд на :8000 нужно запускать
отдельно и перезапускать после тяжёлого прогона. Остальное —
в [docs/testing.md](docs/testing.md).

## ⚡ Производительность

LCP и CLS мерялись по 4–5 заходов: с одного замера доверия им нет.

| Метрика | Было | Стало |
| --- | --- | --- |
| LCP главной (десктоп, без троттлинга) | 867 мс | **288 мс** |
| CLS | сетка скакала на загрузке картинок | **0.00** |
| 20 карточек первого экрана | растровые оригиналы | **≈144 КБ AVIF** |
| TTFB страницы категории (прогретый прод) | — | **≈44 мс** |

Что держит эти цифры и почему это неочевидно из кода (`aspect-ratio` вместо
`display:none`, `connection()` в корне страницы, ровно 4 приоритетные карточки,
набор ширин для AVIF) — в [docs/performance.md](docs/performance.md).

## 🚀 Продакшн

```bash
docker build -t pinly .
docker run -d -p 3000:3000 -v pinly-data:/app/.data \
  -e PINLY_JWT_SECRET="$(openssl rand -hex 32)" \
  -e PINLY_ENV=production \
  -e NEXT_PUBLIC_SITE_URL=https://pinly.example \
  -e PINLY_TRUST_PROXY=1 \
  pinly
```

Без Docker: `npm run build && npm start` рядом с
`uvicorn backend.app:app --port 8000` за nginx или Caddy. Наружу проксируется
только 3000 — `/api/*` уже проксируются внутри Next.

> 💾 **Бэкапить нужно `.data`** — там база и файлы пользователей. `.cache`
> потеря переживёт: он пересоздаётся и прогревается `npm run warm`.

### Переменные окружения

**Обязательные в проде**

| Переменная | Зачем |
| --- | --- |
| `NEXT_PUBLIC_SITE_URL` | домен в `canonical`, OG-ссылках и `sitemap.xml`. Без него всё это указывает на `localhost:3000` |
| `PINLY_JWT_SECRET` | подпись сессий. Иначе секрет генерируется один раз в `.data/secret.key`, а в проде сервер не стартует, если секрет не переживёт перезапуск |
| `PINLY_ENV=production` | включает жёсткие проверки и закрывает сводку событий для посторонних |

**Рекомендуемые**

| Переменная | Зачем |
| --- | --- |
| `PINLY_REQUIRE_SITE_URL=1` | сборка падает, если домен пуст: молчаливый `localhost` в canonical заметен только через неделю пустых кликов |
| `PINLY_TRUST_PROXY` | разрешает читать `X-Forwarded-For`, но только за своим reverse-proxy. Иначе лимиты обходятся одной строчкой в curl |
| `PINLY_OWNER_EMAIL` | единственный аккаунт, которому видна глобальная сводка `/api/ev/summary` |

**Опциональные**

| Переменная | Зачем |
| --- | --- |
| `ACCOUNTS_BACKEND_URL` | адрес Python-бэкенда, если он не на :8000 этой же машины |
| `OPENVERSE_API_KEY` | поднимает лимиты источника с 200/день до 10000/день |
| `EMBED_API_KEY` | включает смысловой поиск, умную ленту и поиск по фото |
| `IMGBB_API_KEY` | внешний хостинг картинок, если своих дисков жалко |
| `PINLY_DATA_DIR` | каталог с базой и загрузками — на другой диск или том |
| `PINLY_DISABLE_RATE_LIMIT` | отключает счётчики частоты. **Только тестовый контур** |

Полный список с комментариями — в [`.env.example`](.env.example).

<details>
<summary>☁️ Фронтенд на Netlify, без бэкенда</summary>

Репозиторий готов к импорту: `netlify.toml` уже настроен. В Netlify —
**Add new site → Import an existing project → GitHub**; команда сборки и плагин
Next.js подтянутся из `netlify.toml`.

- 🐍 Python-бэкенда на Netlify нет. Сайт работает в анонимном режиме (доски и
  лайки в `localStorage`) — это штатный сценарий, а не костыль. Бэкенд поднимается
  отдельно и подключается `ACCOUNTS_BACKEND_URL`.
- 🔗 После первого деплоя задайте `NEXT_PUBLIC_SITE_URL=https://<имя>.netlify.app`
  и сделайте **Clear cache and deploy site**, иначе `canonical` и OG-ссылки
  останутся на старом домене.
- ⚙️ `/api/feed` и `/api/img` работают как Netlify Functions из коробки, их
  поднимает `@netlify/plugin-nextjs`.

</details>
