# Pinly

[![CI](https://github.com/Artemik0922/pinly-web/actions/workflows/ci.yml/badge.svg)](https://github.com/Artemik0922/pinly-web/actions/workflows/ci.yml)

Лента картинок и видео в духе Pinterest, которая целиком живёт у вас. Впереди
Next 16 + React 19 и Tailwind 4, сзади — FastAPI на Python 3.13 с SQLite в WAL,
одним файлом. Загрузки лежат на вашем диске, сессию подписывает ваш же ключ,
картинки отдаёт ваш же прокси. Ни S3, ни Cloudinary, ни чужого OAuth-провайдера:
`docker run` — и сайт вместе со всеми данными пользователей ваш.

Картинки приходят из открытых источников — Openverse, собрания Метрополитен и
Кливленда, Wikimedia Commons, TheMealDB. Все они работают из России без VPN и
не требуют ключей.

## Запуск

```bash
git clone https://github.com/Artemik0922/pinly-web && cd pinly-web
npm ci && pip install -r backend/requirements.txt
python -m uvicorn backend.app:app --port 8000   # аккаунты, доски, события
npm run dev                                     # http://localhost:3000
```

Нужны Node 22 и Python 3.13 — на них проект проверяется в CI. `ffmpeg` нужен,
только если собираетесь загружать видео; без него пин приезжает без постера, а
карточка держит первый кадр сама.

Без второго процесса сайт тоже открывается и работает: лента из открытых
источников, доски и лайки в `localStorage`. Так удобно смотреть репозиторий и
так же его деплоят на статик-хостинг — аккаунтов и чужих досок в этом режиме не
будет.

## Границы

Один узел, одна база, один том. Это не распределённая система и не попытка
сделать кластер: SQLite выбран потому, что его не надо администрировать. Отсюда
же — отказ от сброса пароля (причины разобраны в [docs/privacy.md](docs/privacy.md)).
Мягких удалений тоже нет: снесли аккаунт — данные стёрты каскадом по всем
таблицам.

## Что умеет

- **Лента** — масонри-сетка, инфинити-скролл, ротация категорий, отдельная
  вкладка «Подписки» (`src/components/ui/`, `src/lib/server/`).
- **Пин** — страница с похожими, лайк, скачивание, «поделиться», комментарии,
  теги и автор; с чужого пина можно пожаловаться (`src/components/pin/`).
- **Несколько носителей в пине** — до 8 слайдов, картинка или видео,
  перелистывание свайпом и точками, тихое воспроизведение прямо в ленте
  (`src/components/ui/MediaCarousel.tsx`, `backend/slides.py`).
- **Свои загрузки** — drag&drop, тип файла по сигнатуре байтов, имя придумывает
  сервер, опционально внешний хостинг через ImgBB (`backend/uploads.py`).
- **Доски** — создание, переименование, удаление, коллажи-превью, секретные
  доски, публичная ссылка (`src/components/board/`).
- **Люди** — регистрация и httpOnly-сессия, аватар, публичные профили,
  подписки, комментарии, уведомления о лайке, комментарии и подписке.
- **Поиск** — по названию, описанию, тегам и категории, выдача листается
  курсором. С ключом добавляется смысловой поиск и поиск по фото
  (`src/app/search/`, [docs/embeddings.md](docs/embeddings.md)).
- **Мелочи** — светлая и тёмная тема до первой отрисовки (без мигания), тосты,
  подтверждение удаления, стартовый экран, из знака которого вылетает рой
  летучих мышей.

Про показы, sitemap из БД и «цифры мастеру» — [docs/seo-and-analytics.md](docs/seo-and-analytics.md);
про то, что именно пишется в базу событий и чего там нет — [docs/privacy.md](docs/privacy.md).

## Экраны

| Маршрут | Что на нём |
| --- | --- |
| `/` | лента с фильтром по категориям (`/?category=…`) и вкладкой подписок (`/?feed=subscriptions`) |
| `/category/[slug]` | посадочная страница категории: свой `title`, `h1`, вступление, `canonical` |
| `/pin/[id]` | пин: носители, описание, автор, теги, похожие, лайк, скачивание, комментарии, структурированные данные |
| `/pin/new` | загрузка своих носителей: до 8 слайдов, порядок правят стрелками, первый становится обложкой; доска выбирается сразу |
| `/search?q=…` | поиск по тексту, закрыт от индекса |
| `/search?by=image` | поиск по фото: «Камера»/«Галерея» на телефоне, веб-камера, файл и буфер на ПК; можно перетащить или вставить через Ctrl+V |
| `/boards`, `/board/[id]` | список досок и одна доска; чужая открытая — просмотр и сигнал о проблеме |
| `/profile/[id]` | свой профиль с редактированием и удалением; чужой — витрина с кнопкой подписки |
| `/notifications`, `/media`, `/login`, `/signup` | уведомления, медиатека, вход и регистрация |

## Видео и слайды

Листаются одним механизмом нативного scroll-snap — свайпом, точками, стрелками,
клавиатурой. JS-анимации карусели нет, поэтому она не расходится с нативным
скроллом на телефоне.

Что осталось в коде от отладки этого:

- Видео играет в ленте тихо и по кругу, а пауза вынесена отдельной кнопкой —
  иначе она спорила с кликом по карточке. На странице пина появляются перемотка
  и звук.
- Обложкой всегда остаётся картинка: `ffprobe` снимает длительность и размеры,
  `ffmpeg` кадрирует постер. Поэтому `og:image`, превью доски и сетка про видео
  ничего не знают и не ломаются.
- Раздача умеет `Range`. Без него Safari не играет ролик вовсе, а Chrome
  перекачивает его целиком на каждый шаг ползунка.
- Тип файла определяется по байтам, а не по расширению: `mp4` с содержимым HTML
  не пройдёт.
- Грузится только активный слайд. Замер: 2 МБ за 220 мс на играющем ролике и
  0 байт на двух соседних карточках с видео.

Потолки — 10 МБ на картинку, 60 МБ на видео, 8 носителей на пин; на фронте и в
бэкенде одни и те же, [`src/lib/upload-limits.ts`](src/lib/upload-limits.ts)
обязан совпадать с [`backend/uploads.py`](backend/uploads.py). Как это лежит на
диске — в [docs/architecture.md](docs/architecture.md).

## Откуда контент

| Источник | Что даёт | Категории |
| --- | --- | --- |
| [Openverse](https://api.openverse.org/v1/) | основной поток картинок (flickr, wikimedia и др.) | все |
| [Метрополитен-музей](https://metmuseum.github.io/), [Кливленд](https://openaccess.clevelandart.org/) | собрания общественного достояния | Искусство, Архитектура, Мода |
| Wikimedia Commons напрямую | общий фид и поиск | Природа, Путешествия и остальные |
| [TheMealDB](https://www.themealdb.com/api.php) | блюда с фотографиями | Рецепты |

Запросы кэшируются на диск (`.cache/`), картинки отдаются через собственный
прокси `/api/img`. Один и тот же запрос уходит в API раз в сутки, поэтому
анонимные лимиты Openverse (20 в минуту, 200 в день) перестают быть лимитами
сайта. Если источник недоступен, включается экспоненциальная пауза, его вклад
пустеет, а лента падает на локальные моки — пустых экранов не бывает. Автора
картинки и лицензию видно прямо на странице пина.

`npm run warm` прогревает кэш заранее; без него первый посетитель платит
задержкой чужого API, а не вашего сайта.

## Умная лента и поиск по фото

Оба включаются ключом `EMBED_API_KEY` и индексом `npm run index`. Без них лента
остаётся обычной и ничего не ломается.

Первые ~80% страницы для вошедшего подбираются по вектору вкуса (лайк — вес 1,
сохранение — вес 2), остальные ~20% — обычная ротация категорий. Поиск по фото
гоняет картинку через мультимодальную модель и ищет ближайшие векторы; запрос
фотографией находит и те пины, что проиндексированы по тексту.

Вместо пустой сетки — внятные ответы: без ключа или индекса 503 с объяснением,
что запустить; мусор вместо картинки — 400; больше 5 МБ — 413; провайдер молчит —
502 и кнопка «Попробовать ещё». Модель и провайдера можно поменять через
`EMBED_BASE_URL`, `EMBED_MODEL` и `EMBED_DIMENSIONS`. Почему формат запроса к
роутеру пришлось подбирать перебором — в [docs/embeddings.md](docs/embeddings.md).

## Пара цифр

LCP главной — 288 мс вместо 867, CLS 0.00, 20 карточек первого экрана весят
≈144 КБ в AVIF, TTFB страницы категории на прогретом проде ≈44 мс. Мерялось по
4–5 заходам: с одного замера доверия таким цифрам нет. Что держит эти значения и
почему это неочевидно из кода (`aspect-ratio` вместо `display:none`,
`connection()` в корне страницы, ровно 4 приоритетные карточки, набор ширин для
AVIF) — в [docs/performance.md](docs/performance.md).

## Проверки

```bash
npm run typecheck   # next typegen + tsc --noEmit
npm run lint        # eslint
npm run test:api    # pytest: валидация, права, каскады, кэш, носители — без сети
npm run test:e2e    # Playwright: лента, регистрация, комментарий, поиск, доска, видео
npm run ui:audit    # дизайн-система по вычисленным стилям (нужен запущенный сервер)
npm run build       # продакшн-сборка
```

Сейчас это 97 pytest-тестов и 23 Playwright-сценария. Дизайн-аудит прогоняет 14
маршрутов в двух вьюпортах и следит за шкалой ширин, радиусами, сеткой отступов
в 4 px, размером тап-цели и горизонтальным скроллом. CI
([`.github/workflows/ci.yml`](.github/workflows/ci.yml)) гоняет это тремя
работами: `frontend`, `backend` и `e2e`, которая стартует только после двух
зелёных.

Два предупреждения, которые экономят полдня: адрес прогона обязан быть
`http://localhost:3000` (не `127.0.0.1`), а бэкенд на :8000 нужно запускать
отдельно и перезапускать после тяжёлого прогона. Остальное —
[docs/testing.md](docs/testing.md).

## Продакшн

```bash
docker build -t pinly .
docker run -d -p 3000:3000 -v pinly-data:/app/.data \
  -e PINLY_JWT_SECRET="$(openssl rand -hex 32)" \
  -e PINLY_ENV=production \
  -e NEXT_PUBLIC_SITE_URL=https://pinly.example \
  -e PINLY_TRUST_PROXY=1 \
  pinly
```

Без Docker: `npm run build && npm start` рядом с
`uvicorn backend.app:app --port 8000`, за nginx или Caddy. Наружу проксируется
только 3000-й порт — `/api/*` проксируются внутри Next.

Бэкапить нужно `.data`: там база и файлы пользователей. `.cache` потеря
переживёт, он пересоздаётся и прогревается `npm run warm`.

### Переменные окружения

| Переменная | Когда нужна |
| --- | --- |
| `NEXT_PUBLIC_SITE_URL` | в проде обязательно: домен в `canonical`, OG-ссылках и `sitemap.xml`. Без него всё это указывает на `localhost:3000` |
| `PINLY_JWT_SECRET` | в проде обязательно: подпись сессий. Без переменной секрет генерируется один раз в `.data/secret.key`, а сервер не стартует, если секрет не переживёт перезапуск |
| `PINLY_ENV=production` | включает жёсткие проверки и закрывает сводку событий для посторонних |
| `PINLY_REQUIRE_SITE_URL=1` | сборка падает, если домен пуст: молчаливый `localhost` в canonical заметен только через неделю пустых кликов |
| `PINLY_TRUST_PROXY` | разрешает читать `X-Forwarded-For`, но только за своим reverse-proxy. Иначе лимиты частоты обходятся одной строчкой в curl |
| `PINLY_OWNER_EMAIL` | единственный аккаунт, которому видна глобальная сводка `/api/ev/summary` |
| `ACCOUNTS_BACKEND_URL` | адрес Python-бэкенда, если он не на :8000 этой же машины |
| `OPENVERSE_API_KEY` | поднимает лимиты источника с 200/день до 10000/день |
| `EMBED_API_KEY` | включает смысловой поиск, умную ленту и поиск по фото |
| `IMGBB_API_KEY` | внешний хостинг картинок, если своих дисков жалко |
| `PINLY_DATA_DIR` | каталог с базой и загрузками — на другой диск или том |
| `PINLY_DISABLE_RATE_LIMIT` | отключает счётчики частоты. Только тестовый контур |

Полный список с комментариями — в [`.env.example`](.env.example).

<details>
<summary>Фронтенд на Netlify, без бэкенда</summary>

Репозиторий готов к импорту: `netlify.toml` уже настроен. В Netlify —
**Add new site → Import an existing project → GitHub**, команда сборки и плагин
Next.js подтянутся из `netlify.toml`.

Python-бэкенда на Netlify нет, поэтому сайт работает в анонимном режиме — доски
и лайки в `localStorage`. Это штатный сценарий, а не костыль; бэкенд поднимается
отдельно и подключается `ACCOUNTS_BACKEND_URL`. `/api/feed` и `/api/img` работают
как Netlify Functions, их поднимает `@netlify/plugin-nextjs`.

После первого деплоя задайте `NEXT_PUBLIC_SITE_URL=https://<имя>.netlify.app` и
сделайте **Clear cache and deploy site**, иначе `canonical` и OG-ссылки останутся
на старом домене.

</details>

## Лицензия и участие

Лицензии в репозитории нет — формально все права защищены, и это дыра, которую
надо закрыть, прежде чем просить чужие пул-реквесты. `CONTRIBUTING.md` и
`SECURITY.md` тоже не написаны: если находите уязвимость — пишите автору, не
открывайте публичный issue. Публичного демо нет; сайт разворачивается командами
из раздела «Запуск».

Минимум для любого изменения:
`npm run typecheck && npm run lint && npm run test:api && npm run test:e2e`,
правка контракта API — только вместе с тестом в `backend/tests/test_contract.py`.
Если локально всё зелёное, а CI красный, почти всегда это одна из ловушек из
`docs/testing.md`.
