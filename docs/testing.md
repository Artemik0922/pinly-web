# Проверки: чем и как мерить, и где тесты врут

## Команды

```bash
npm run typecheck          # next typegen + tsc --noEmit
npm run lint               # eslint
npm run test:api           # pytest: валидация, права, каскады, кэш, носители — без сети
npm run test:e2e           # Playwright: лента, регистрация, комментарий, поиск,
                           #               категория, превью доски, её цифры, видео и слайды
npm run ui:audit           # дизайн-система: ширины, радиусы, сетка, тап-цели,
                           #               кегль на 390 и 1280 (нужен запущенный сервер)
npm run seo:report         # что краулер и мессенджер видят без JavaScript
npm run build              # продакшн-сборка
```

Текущий прогон: **97 pytest** + **23 Playwright** + аудит 34 проверки.

## CI

[`.github/workflows/ci.yml`](../.github/workflows/ci.yml) гоняет тремя работами:
`frontend` (типы, линт, сборка на Node 22), `backend` (pytest на Python 3.13) и
`e2e`, которая стартует только после двух зелёных.

Второй рабочий файл — [`warm.yml`](../.github/workflows/warm.yml): каждый час в
:17 он запускает `node scripts/warm.mjs` по адресу из секрета `WARM_URL` и греет
кэш прода. Без секретов задача проходит пусто, так что форкать репозиторий
безопасно.

## Gotcha №1 — origin обязан быть `http://localhost:3000`

Не `127.0.0.1`. Next 16 блокирует dev-ресурсы по чужому origin, гидрация не
доходит, и каждый селектор клиентского компонента падает как «элемент не найден».
Вид у этого сбоя обманчивый: кажется, что сломан компонент, а сломан адрес.
Один прогон на `127.0.0.1` съедал полдня, пока причина не была найдена в
трейсе сети.

## Gotcha №2 — бэкенд на :8000 нужно запускать отдельно

`test:e2e` поднимает dev-сервер сам, а Python-бэкенд — нет. Лимиты частоты
живут в памяти процесса, поэтому после тяжёлого прогона бэкенд лучше
перезапустить: иначе 429 выглядит как сломанная фича.

## Gotcha №3 — pytest запускается без `PINLY_DISABLE_RATE_LIMIT`

Флаг отключает счётчики «не спамь» целиком, а тест на лимит лайков проверяет
именно 429. С экспортированным флагом набор перестаёт быть осмысленным: он
зелёный, но ничего не утверждает.

## Gotcha №4 — часть проверок зависит от ffmpeg

Тесты видеопина (постер, длительность, раздача по диапазонам) снимают артефакты
через `ffprobe`/`ffmpeg`. В pytest они помечаются skip, а не fail: отсутствие
программы — это не сломанная фича, но и зелёный прогон в этом случае работу
видео не доказывает.

Смоук в браузере проверяет настоящий путь и пропускать не умеет: он требует
постер. Поэтому в CI (`backend` и `e2e`) ffmpeg ставится отдельным шагом, а не
надеется на образ раннера — Playwright качает свой ffmpeg для кодеков браузера,
и бэкенду он не доступен.

## Что делает `ui:audit`

Замеряет вычисленные стили на 17 адресах × 2 ширинах (живые `/board`, `/profile`
и `/pin` берутся из `sitemap.xml`, а не из памяти) и сверяет с [`DESIGN.md`](../DESIGN.md):
шкалы ширин, радиусы, сетка 4 px, кегль ≥ 11 px, тап-цели ≥ 40 px, отсутствие
горизонтального переполнения. Падает на нарушении — не «на вкус», а на числе.

Правила записаны в DESIGN.md не для красоты: без них новый экран приносит
«ещё одну красивую ширину контейнера», и ритм рассыпается незаметно.

## Где границы тестов

- Локальная база в `.data` — мусор смоук-прогонов, а не продакшн-снимок. Цифры
  из `seo:report` на ней честны как замер механики, но не как аудит контента.
- `test:e2e` идёт одним воркером (`--workers=1`): часть сценариев трогает
  счётчики частоты и общую базу, параллель их ломает.
- Тесты не покрывают реальные внешние API: Openverse, музеи и RouterAI
  проверяются смоуком в браузере и `npm run probe:embeddings`.
